## 2. 초급 13일

기존 일차와 순서는 보존하며, 완료한 7일 뒤에 새 코스 6일을 붙였다.

| 일차 | 주제 |
| --- | --- |
| 1–7 | DRINK, GO, TAKE, MAKE, STUDY, MEET, READ |
| 8–11 | HAVE, GET, DO, KEEP |
| 12–13 | BUT, BECAUSE |

새 일차도 동일하게 배우기 2 → 조립 3 → 문장 확장 2 → 독립 적용 1, 총 8개 활동이다. 전부 합계 **13 × 8 = 104개 활동**.

BUT·BECAUSE는 '동사'가 아니라 **접속사**이므로 홈은 '오늘의 핵심 표현'으로 표시한다. 예: `I am tired, but I want to walk.` / `I study English because I want to travel.`.

학습 진도는 기존 `judongmok:learner-progress:v1` 키에 저장한다. 기존 7일 완주자는 8일차부터 이어갈 수 있다.

## 3. 카카오톡 내장 브라우저 음성

문제 완료 직후 자동 재생은 하지 않는다. 사용자가 `🔊 문장 듣기` 버튼을 직접 누를 때만:

1. Netlify 서버 함수 `/.netlify/functions/jm-audio`에 영어 문장을 짧게 전송한다.
2. 서버에서 음원 생성 API를 호출해 **MP3 파일**로 반환한다. 비밀 API 키는 브라우저로 보내지 않는다.
3. 모바일 WebView가 프로그램 재생을 차단하면 **브라우저 기본 오디오 재생 컨트롤**이 나타나 사용자가 다시 ▶를 누를 수 있다.
4. 서버 TTS가 준비되지 않았다면 브라우저 내장 음성 합성으로 대체를 시도한다. 그마저 없으면 카카오톡 메뉴의 '다른 브라우저로 열기'를 안내한다.

**중요:** 카카오톡 실제 단말의 오디오 동작 및 Netlify 최신 배포/키 유무를 확인하지 못했다. 위는 구현 구조이며 실기기 보장은 아직 아니다.

## 4. 말하기 일기

`홈 → 오늘의 말하기 일기`

- 한국어로 **🎤 말하기** 또는 음성 파일 선택/직접 입력
- 한국어 음성 파일 → `jm-diary-transcribe` → 인식된 원문을 사용자가 확인·수정
- `자연스러운 영어로 바꾸기` → `jm-diary-english` → 간단하고 자연스러운 영어 문장 생성(사실 유지)
- 영어 문장 읽기 및 **🎙️ 직접 녹음**
- 녹음을 확인한 다음에만 일기 저장 가능
- 지난 일기에서 한국어·영어 글과 내 음성 녹음을 복습

브라우저가 마이크/MediaRecorder를 지원하지 않으면 휴대폰 녹음 파일 선택 및 글 입력으로 우회할 수 있다. **영어 발음 자동 채점은 현재 구현되지 않았다.**

## 5. 저장과 개인정보

- 일반 학습 진도: 브라우저 `localStorage`(`judongmok:learner-progress:v1`)
- 일기 한국어·영어 텍스트: 브라우저 `localStorage`(`judongmok:diary:v1`)
- 일기 영어 음성 녹음 파일: 해당 브라우저의 `IndexedDB`(`judongmok-diary-audio-v1`)
- 음성 인식과 영어 변환을 요청할 때는 내용이 Netlify Function을 통해 AI 서비스로 전송된다. 이 앱의 별도 서버 DB에 저장하는 코드는 없음.
- 카카오톡 내부 브라우저, 크롬/사파리는 저장 공간이 달라 **다른 브라우저·다른 기기 사이에 자동 동기화되지 않음**. 브라우저 데이터 삭제 때 기록·녹음 파일이 사라질 수 있음.
- 개인정보/일기 내용을 소스 코드나 로그에 기록하지 않으며, API에 사용자 이야기를 임의로 덧붙이지 않도록 지시함.

## 6. 외부 API 연결과 비용

세 개의 Netlify Functions 파일:
- `netlify/functions/jm-diary-transcribe.mjs` (OpenAI `gpt-transcribe`)
- `netlify/functions/jm-diary-english.mjs` (`gpt-5.4-mini`)
- `netlify/functions/jm-audio.mjs` (MP3 TTS `gpt-4o-mini-tts`)

Netlify 신형 credit-based 플랜에서는 **AI Gateway**가 `OPENAI_API_KEY`, `OPENAI_BASE_URL`을 자동 주입할 수 있어 코드가 이를 사용하도록 구성했다. 다만 **audio transcription/TTS API 경로가 Gateway에서 지원되는지는 검증되지 않았다.** Gateway에서 해당 경로를 처리하지 못하면 Netlify 프로젝트의 **환경변수**에 별도 `JM_OPENAI_API_KEY`를 Functions scope로 설정해야 한다. 키는 GitHub에 절대 올리지 않는다.

Netlify UI: `Project configuration → Environment variables → Add variable`에서 `JM_OPENAI_API_KEY`를 등록하고 새 배포를 확인한다. OpenAI API 사용량과 Netlify 호출에 별도 비용이 발생할 수 있다. ChatGPT/Claude 구독과 별개다.

API 남용 방지: Netlify Function에 IP당 분당 호출 제한(음성 인식 6회, 영어 변환 12회, MP3 30회)을 설정했다. 배포 로그에서 규칙 반영을 확인해야 한다. 이는 절대적인 전체 월간 예산 상한이 아니다.

주의: `gpt-4o-mini-tts` Speech API는 2027-01-06 폐지 예정이라고 공급자가 공지했으므로, 운영 전 음성 생성 모델 업데이트를 계획해야 한다. 현재 실제 공급자 응답을 확인하지 못했다.
