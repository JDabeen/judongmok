## 핵심 제품 가설

한국어 사용자, 특히 50~60대 초급자가 복잡한 설명 없이 **한국어와 영어 어순의 차이를 체감**하고, **혼자 문장을 만들고**, **짧은 문장을 장소·시간으로 확장**하는 첫 성공을 경험하도록 한다.

UX 원칙:
- 한 화면에 한 질문. 불필요한 제목·안내·단계 라벨 최소화.
- 기존 v08 주동목의 카드/선택지/색상 체계 유지; 큰 글자와 큰 터치 영역.
- 주어·동사·목적어 라벨은 **첫 단계에서만 작게** 표시; 이후 없애기.
- 시청자의 ‘영어 문장 원리를 이해했다’는 경험이 실제 능력 향상으로 이어지는지는 **미검증**.

## 공유 링크와 저장 동작

- `/preview-v2/`: 처음 보는 브라우저에서는 튜토리얼. 같은 브라우저에서 튜토리얼 완료 기록이 있으면 홈.
- `/preview-v2/?tutorial=1`: 기존 기록이 있어도 튜토리얼 첫 화면에서 시작. **저장된 진도·복습을 초기화하지 않음**.
- 현재 V2 진도는 이 체험판의 `localStorage`에 저장. **기기/브라우저 사이에 동기화되지 않음**. 브라우저 데이터 삭제·시크릿 모드에서는 초기화될 수 있음.
- 정식 앱의 Supabase 익명 인증, 관리자 대시보드, 데이터베이스 기록, 푸시 알림과 **현재 V2는 연동하지 않음**.

## 구현 검증 범위와 미검증

확인함:
- GitHub에 V2 코드 저장, JavaScript 구문 검사.
- 모의 화면 이벤트 실행으로 최초 진입 → 튜토리얼 1·2·3단계 → 홈 이동 확인.
- 초급 7일 연속 완료 처리, 복습 내역 7개 저장, 재진입 시 홈 유지 확인.
- `?tutorial=1`일 때 튜토리얼 첫 화면 진입, 일반 링크일 때 기존 홈 진입 및 진도 보존 확인.

아직 확인하지 않음:
- 실제 Netlify 공개 URL에 최신 코드가 배포됐는지 독립 확인.
- iPhone/Android 실기기의 카드 배치·글자 크기·음성/음량·진동·공유.
- 처음 보는 사람이 설명 없이 완주하는지, 진짜 학습 효과/재방문 효과가 있는지.
- 모든 예문의 원어민 사용 맥락 검수 및 학습 난이도 검증.

## 현재 가장 큰 미해결 문제

**튜토리얼에서 느낀 ‘아! 영어가 이렇게 되는구나’라는 감정이 홈의 ‘오늘의 연습 시작’까지 이어지는가?**

실제 피드백: 홈은 아직 다소 애매하며 튜토리얼과 시각적 톤은 같되 **경험상 구분**되어야 한다. 홈 카드·콘텐츠를 더 늘리기 전에 첫 사용자 반응을 관찰하기.

## 다음 작업 우선순위

1. **외부 사용자 1명에게 공유 링크만 보내기**. 미리 사용법을 설명하지 않고, 어디서 막혔는지/어디서 재미를 느꼈는지/계속하고 싶었는지를 확인.
2. 시니어 사용자(50~60대) 3~5명으로 확대하기 전, **홈의 의미와 다음 행동**이 직관적인지 검증하기.
3. 홈을 튜토리얼과 같은 디자인 언어로 유지하면서도 **진도·학습 목표 중심의 별도 공간**처럼 느껴지도록 개선하기.
4. 실제 회화·빈도와 채널 기존 콘텐츠(동사 8개, 어순/방장시유)를 연결해 초급 7일 콘텐츠 검수하기. AI가 생성한 듯 어색한 문장은 교체.
5. 중급·고급 커리큘럼은 사용자 검증 후 확장. 불필요한 기능/긴 설명/과도한 메뉴 추가 지양.
6. 필요성이 확인되면 그때 V2와 정식 앱의 인증·DB·운영 기능 통합을 검토.

## 후속 작업 시 주의사항

- **`index.html`은 정식 서비스이므로 명시적 요청 없이 수정하지 않는다.** UX 실험은 `preview-v2/index.html`에서만 수행.
- 첫 단계의 작은 문장 성분 라벨 외에는 문제 풀이 중 중복 설명을 최소화.
- ‘100배 재미’, ‘학습 효과’를 사실로 주장하지 않기. 축하 효과는 독립적인 정답·문장 완성의 체감에 종속되어야 함.
- 다음 디자인 작업은 화면을 먼저 통째로 바꾸지 말고 **홈이 왜 모호한지 사용자 반응에서 문제를 정의한 뒤** 설계한다.


## 추가 작업 — 모바일 UI 및 하루 학습 개편 (2026-11-15)

**발견한 문제**
- 이전 초급 7일 코스는 하루에 기본 문장 한 번 조립 → 표현 하나 추가로 끝나서 반복·적용 경험이 부족했음.
- 좁은 휴대폰에서 긴 표현의 조립 칸, 버튼 너비와 가로 스크롤에 대한 명시적인 대응이 부족했음.
- 이미 7일을 끝낸 브라우저에서 새 일일 학습을 다시 진입하기 어려웠음.

**변경한 학습 코스**

기존 `/preview-v2/`의 초급 코스를 **하루 8개 활동**으로 변경함.

| 순서 | 단계 | 실제 활동 |
| --- | --- | --- |
| 1–2 | 배우기 | 같은 동사의 자연스러운 짧은 예문 2개를 보고, 영어 음성 듣기 선택 |
| 3–5 | 조립하기 | 같은 동사로 서로 다른 문장 3개를 스스로 단어 순서대로 조립 |
| 6–7 | 문장 늘리기 | 장소·시간 등 구절을 붙여 완성하는 2문제 |
| 8 | 혼자 만들기 | 처음 제시되는 긴 문장을 4~5개 영어 구절로 조립 |
| 완료 | 성취 | 성공 효과, 영어 음성 듣기, 공유, 홈 이동 |

기존 7일 동사(현재 초급 샘플): **DRINK, GO, TAKE, MAKE, STUDY, MEET, READ**.

추가 기능: 각 활동 및 조립 도중 브라우저에 임시 진도를 저장하고 홈에서 `이어서 연습하기`로 복귀. 이미 7일 완주한 학습자는 `기초 문장 다시 연습`으로 첫날부터 다시 사용 가능. 음성 기능을 지원하지 않는 브라우저에는 안내 표시.

**검증 결과 및 한계**
- 전체 7일 × 8개 활동의 모의 클릭 흐름 검증(7일 완료, 문장 선택 총 111회, 복습 기록 저장).
- 잘못 고른 선택지는 진도 변경 없음, 조립 중 새로고침 후 복귀, 7일 완료 후 다시 연습, 튜토리얼 공유 링크의 기록 보존 테스트.
- 지난 문장 정답 펼치기, 복습 음성 듣기, 일일 학습 예문 듣기, 학습 홈·코스 목록 이동 확인.
- 320 / 375 / 390 / 430px 모바일 뷰포트에서 **11종 화면(첫 화면, 1·2·3단계, 홈, 배우기, 문장 늘리기, 혼자 만들기, 완료, 복습, 코스 목록) × 4가지 폭 = 44회 정적 레이아웃 검사**를 브라우저로 실행. 초기 검사에서 복습·코스 목록의 작은 버튼 터치 영역 문제를 발견해 크기를 수정했고 재검사 **44/44 통과**(가로 넘침 없고 버튼 가로/세로 40px 이상).
- **중요**: 이 모바일 테스트는 기존 디자인 CSS와 새 반응형 규칙을 적용한 **대표 화면 테스트**이며, 실제 Netlify에 올라간 전체 앱을 휴대폰에서 직접 작동시키며 검증한 것은 아니다. Netlify의 배포 성공 여부도 외부에서 확인되지 않았다.
- 새로 추가한 8개 활동의 교육효과, 음성 품질, 모바일 터치 및 배포 반영은 **외부 실사용자 검증 필요**.

사용자가 모바일에서 이전 기능이 작동하지 않는다고 보고했으므로, **배포 버전 확인 및 실기기 확인**은 해결된 것으로 표시하지 않는다.

**기존 정식 서비스** `/index.html`과 관리자·DB 코드는 이번 수정에 포함하지 않는다.
